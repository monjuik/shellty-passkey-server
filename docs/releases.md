# Releases

Push a stable version tag to build and publish a GitHub Release:

```sh
git tag v0.9.0
git push origin v0.9.0
```

Choose an unused version and tag the commit you intend to ship. The workflow
accepts only `vX.Y.Z`.

Every target runs tests, vet, and a native check of the built binary's version.
A separate Ubuntu job runs the full suite with PostgreSQL 16 and the race detector.
Publication waits for all checks and six builds. Release notes are generated by
GitHub. An existing release is not overwritten; rerunning an already published
version fails. 

## Downloads

Each release includes amd64 and arm64 builds for Linux, macOS (`darwin`) and
Windows. Archives follow this naming convention:

```text
shellty-passkey-server_0.9.0_linux_amd64.tar.gz
shellty-passkey-server_0.9.0_darwin_arm64.tar.gz
shellty-passkey-server_0.9.0_windows_amd64.zip
```

Each archive contains one directory with `passkey-server` (or `.exe`),
`config.example.json`, README, LICENSE, documentation and dependency licenses/notices.
The server embeds its UI and migrations. The demo is available from source only.
Binaries are built with CGO disabled. Platform signing, notarization, installers
and an automated SBOM are not included in this workflow.

`SHA256SUMS` covers all six archives. For example, after downloading the files:

```sh
sha256sum --check SHA256SUMS
```

On macOS, use `shasum -a 256 --check SHA256SUMS`. In PowerShell, use
`Get-FileHash <archive.zip> -Algorithm SHA256` and compare with the corresponding
entry. Checksums verify file integrity; they are not a publisher signature.

## Version and local packaging

```sh
./passkey-server --version
# passkey-server 0.9.0
```

This command needs no configuration, certificates or database. A normal source
build reports `passkey-server dev`.
